Is k-means dead?

In November 2026, Meta published e-means, a new take on k-means. They claim it finds groups that are just as good in about a tenth of the time. This page lets you test that claim yourself, with three small experiments that run on your own device.

k-means · 195725

Goes through all of the data, moves every group's centre once, then starts again. It usually does this 25 times.

e-means · 2026~3

Looks at a small handful of data at a time and nudges the centres a little after each one. It goes through all the data about 3 times.

Two terms used on this page
One readGoing through every data point once. Fewer reads means less work.
Grouping errorHow far, on average, each point sits from the centre of its group. Lower means tighter, better groups.

In every experiment, both algorithms run at the same time, start from the same random centres and use the same code to measure distances. So any difference you see comes from the algorithm itself.

Experiment 1 of 3

How quickly can each one sort 60,000 handwritten digits?

What we're testing: Meta's main claim. Both algorithms get the same images of handwritten digits (0 to 9) and sort them into groups of look-alikes. We time how long each one takes and check whether e-means' groups are just as good.

  1. Pick how many digits to sort. More digits means more work, so the gap between the two becomes easier to see.
  2. Pick how many groups to make. More groups means finer groups, for example separating a slanted 7 from an upright one.
  3. Press Run experiment and watch both work side by side.

Experiment 2 of 3

Does e-means help on a small, simple task like repainting a photo with 16 colours?

What we're testing: whether the speed-up matters on everyday data. Every pixel is a point made of three numbers: how red, green and blue it is. Each algorithm groups similar colours, uses each group's average as one paint colour, then repaints every pixel with its group's colour. Meta's paper says e-means shines on large, complex data, so here we expect a much smaller difference.

  1. Pick a photo, or upload your own. Your photo is processed on your device and never uploaded anywhere.
  2. Pick how many colours to use. Fewer colours is harder, because each colour has to stand in for more of the photo.
  3. Press Run experiment and compare the two repainted photos.

Experiment 3 of 3

Does the time saved grow as the data grows?

What we're testing: when switching to e-means is worth it. We run the digit-sorting task from Experiment 1 three times, on 1,000, then 10,000, then 60,000 digits, making 49 groups each time.

  1. Press Run experiment. The three sizes run one after another.
  2. Compare the bars in each row. The grey bar is k-means' time and the coral bar is e-means' time. The number on the right is how many times faster e-means was.

How we kept this a fair test
  • Both algorithms run at the same time, each on its own CPU core, and use exactly the same code to measure distances. The difference comes from the algorithm, not the code.
  • Both start from the same randomly chosen centres. Grouping error is measured the same way for both, on every point, after the clock stops.
  • e-means here is a line-by-line copy of Meta's own code (faiss 1.16), translated to JavaScript. It picks the same settings theirs does.
  • Times depend on your device, and slower phones take longer. Each run starts from new random centres, so results vary slightly between runs. Meta's own code behaves the same way.
